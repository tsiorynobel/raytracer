# 0003 — Use Catch2 for Unit Testing

## Status

Proposed

## Context

The course follows a TDD workflow, so the testing framework needs to be easy
to read and write for participants who may be new to C++ testing. The raytracer
involves floating-point arithmetic, so approximate comparisons must be
supported.

Alternatives considered:

- **GoogleTest** — widely used in industry, but more verbose setup and
  `ASSERT_*` / `EXPECT_*` macros are less readable for teaching purposes.
- **doctest** — similar syntax to Catch2 and lighter compile times, but a
  smaller ecosystem and less documentation.
- **Boost.Test** — mature, but requires Boost as a dependency, which is heavy
  for a small project.

## Decision

Use Catch2 v3, fetched via CMake `FetchContent`. Tests are written with
`TEST_CASE` and `REQUIRE` / `CHECK` macros. `Catch::Approx` handles
floating-point comparisons. `catch_discover_tests` registers all test cases
with CTest.

## Consequences

**Positive:**
- `TEST_CASE("description", "[tag]")` and `REQUIRE(expr)` read like plain
  English, making tests easy to follow in a live-coding session.
- `Catch::Approx` provides built-in support for the floating-point comparisons
  that appear throughout a raytracer.
- No separate `main()` required when linking `Catch2::Catch2WithMain`.

**Negative:**
- Catch2 v3 is a compiled library (unlike the older single-header v2), so
  initial build times are longer.
- Less commonly seen in production C++ codebases than GoogleTest; participants
  may need to learn a second framework in a professional context.
- `FetchContent` pins to a specific tag (`v3.7.1`); updating requires a manual
  change to `CMakeLists.txt`.
